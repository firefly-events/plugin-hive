# Planning Queue Structured Outline Insight

The planning-queue outline works best when the six vertical slices are treated as the primary document skeleton and the generic structured-outline template is treated as the outer frame. The issue-specific phase requirements are stricter than the template's normal "Changes / Interfaces / Validation" section shape, so each phase needs a repeated mini-contract: working state, approach, manifest, risks, and interfaces.

The most reusable planning pattern is to separate "locked decision" from "implementation uncertainty." For this epic, G1-G4 and the fork defaults resolve the main architecture questions; unresolved items such as exact PAT scopes, Slack credential availability, or label-create API behavior should be documented as implementation checks, not reopened as sign-off decisions.
