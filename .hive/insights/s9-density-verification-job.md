# s9-density-verification-job — insights

- **Epic branch can be held by a peer worktree.** `git checkout feat/kg-repair-activation` fails with "already used by worktree" in Multica's shared bare-repo layout. Workaround that preserves the integration contract: `git reset --hard origin/<epic-branch>` on the daemon's agent branch, then `git push origin HEAD:<epic-branch>`. No need to own the branch name locally.
- **Stub `gh`/`git` via PATH-prepended shell scripts, not mocks.** The script invokes both through `spawnSync`, so a temp `bin/` with logging stubs gives full assertion power (`stub.log` records every argv) without touching a real repo or GitHub. `GH_PR_LIST_OUTPUT` env var lets one stub serve both "no PR" and "PR exists" idempotency cases.
- **`node:` builtin sqlite is still not the repo convention** — existing kg scripts shell out to `python3 -c "import sqlite3..."` so they run without `node_modules` (better-sqlite3 is declared but rarely installed in agent worktrees). Followed that; tests build fixtures the same way (see `scripts/tests/kg-stats.test.mjs`).
- **Idempotency check must precede the branch dance.** Checking `gh pr list --head <branch> --state open` before any `git checkout -B` means a re-run with an open PR leaves the working tree completely untouched — easier to verify and safer in CI.
- **Restore-branch in `finally`.** The script switches to the bump branch to commit; wrapping the PR creation in try/finally with `git checkout <previous>` guarantees the caller's branch survives a mid-flight `gh` failure (run() exits the process, but the finally still fires on thrown JS errors; acceptable trade-off documented here).
